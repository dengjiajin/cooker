# 到家服务平台第一期底座实现计划

> **给执行型 agent：** 必须使用任务清单逐项推进。适合后续切换到 `subagent-driven-development` 或 `executing-plans` 执行。步骤使用 `- [ ]` 复选框追踪。

**目标：** 完成到家服务平台第一期底座能力建设，跑通“用户微信登录 -> 发起厨师入驻申请 -> 后管审批 -> 生成厨师身份 -> 厨师端登录与首次改密”主链路。

**架构：** 系统按用户域、服务者域、交易域、平台治理域四个稳定域组织。本期只实现用户域、服务者域、平台治理域的落地能力，交易域只保留扩展位。后端使用 Spring Boot 3 单体应用承载多域模块，后管使用 Vue 3，两个小程序使用原生微信小程序。

**技术栈：** `Spring Boot 3`、`MyBatis-Plus`、`MySQL`、`Redis`、`Sa-Token`、`Vue 3`、`Vite`、`TypeScript`、`Element Plus`、`Pinia`、原生微信小程序

## 三、并行开发建议

在底座和接口边界冻结后，可并行拆分为以下主线：

- A 线：后端底座与 RBAC
- B 线：用户域与服务者域后端
- C 线：后管前端
- D 线：客户端小程序
- E 线：厨师端小程序

串行前置条件：

- 后端基础工程结构确定
- 核心表结构确定
- 接口命名与返回结构确定

## 四、验收标准

- 用户能通过客户端微信登录并进入用户表
- 后管用户列表能看到该用户
- 用户能在“我的”中提交入驻申请
- 后管能审批、驳回、查看历史
- 审批通过后生成正式厨师身份
- 后管厨师列表能看到该厨师
- 厨师能用手机号和初始密码登录
- 首次登录必须强制修改密码
- 后管 RBAC 可用，至少支持管理员登录与菜单权限加载
